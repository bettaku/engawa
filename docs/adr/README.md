## 状態の定義

| 状態 | 意味 |
| --- | --- |
| 提案 | 草案。レビューと「採用前に検証すること」の実施を待っている。この状態のADRを根拠に実装を固定しない |
| 採用 | 検証項目を満たし、「要判断」がすべて決まった。以後の実装はこの判断に従う |
| 却下 | 採らないと決めた。理由を残すためにファイルは消さない |
| 置換 | 後のADRで置き換えた。冒頭に置換先の番号を書く |
| 廃止 | 対象がなくなり、判断が不要になった |

状態を変えるときは、冒頭の「状態」と目次の両方を更新し、変更日と根拠（PoCの結果、IssueやPRの番号）を本文に追記する。採用済みのADRの判断を変えるときは、本文を書き換えずに新しいADRを作り、古いほうを「置換」にする。

## 書式

ファイル名は`NNNN-英小文字の短い題名.md`とする。番号は4桁の連番で、欠番を再利用しない。本文は日本語で書き、次の見出しをこの順に置く。

```markdown
# ADR-NNNN: 題名

- 状態: 提案
- 作成日: YYYY-MM-DD
- 関連: 計画の節、ほかのADR、Issue / PR

## 背景
判断が必要になった事情と、現行実装の事実。事実には参照先（ファイル、コミット、URL）を付ける。

## 検討した選択肢
採らなかった案と、採らない理由。

## 決定案
採る案。「提案」の間は確定事項ではない。

## 採用前に検証すること
決定案を「採用」にする前に確かめる項目。PoCで確定する項目はここに書き、決定案に混ぜない。

## 影響
採用した場合に変わること、増える作業、残るリスク。

## 要判断
人の判断が要る点。選択肢と推奨を書く。なければ「なし」。

## 出典
外部資料のURLと確認日。
```

## 外部情報の書き方

- ライブラリの版、MSRV（ビルドに必要なRustの最低版）、公開日は、crates.io・docs.rs・各プロジェクトの公式資料で確認し、確認日とURLを「出典」に書く。
- 確認できなかった項目は「未確認」と書く。記憶や推測で埋めない。
- 版の情報は古くなる。実装を始めるとき、および状態を「採用」に変えるときに再確認し、確認日を更新する。確定した版は`Cargo.lock`と`rust-toolchain.toml`が正であり、ADRの表はその時点の根拠として残す。
