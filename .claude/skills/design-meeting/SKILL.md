議題: $ARGUMENTS

あなたは提案者兼書記、Codex はレビュアー。以下を最大 3 ラウンド回す。

0. 開始前に git status を確認する。未コミットの変更があれば、何もせず報告して止まる。
1. 関連するコードを読み、docs/design/<議題の短い英語スラッグ>.md に設計案を書く。
   背景、現状の問題、提案、代替案、移行手順、ロールバック手順の節を含める。
2. codex:codex-rescue サブエージェントに次の形で依頼し、完了を待つ。
   「$design-reviewer スキルに従って docs/design/<スラッグ>.md をレビューして。ラウンド N。」
   2 ラウンド目以降は前回の Codex スレッドの続きとして依頼し、
   前回の各指摘 ID に対する分類（採用・反論・要判断）と、反論の理由を添える。
3. 指摘を ID ごとに「採用」「反論（理由付き）」「要判断」に分類し、採用分を設計書に反映する。
4. Codex の総評が「重大度・高の未解決指摘：なし」になるか、3 ラウンド終えたら終了する。

終了後、次を行う。
- 設計書の末尾に「議事録」節を追記する（ラウンドごとの指摘と対応）。
- git diff で、設計書以外のファイルが変更されていないことを確認する。
- 実装には進まず、「要判断」事項の一覧だけをユーザーに報告して止まる。
